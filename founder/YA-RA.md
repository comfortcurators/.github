## What this obliges, in the founder's terms and not an agent's

Four things are stated on that page that no repository currently satisfies, and
they are recorded here as open, not as done:

1. **Curator eats everything.** *"Feed Curator and install oesophagus — all
   repository, all intent, all patterns."* Curator observes and learns today,
   but nothing feeds it the org's own repositories, and no repository's Intent
   and Pattern lines are readable by it as data. They are prose in fourteen
   `CLAUDE.md` files. The oesophagus does not exist yet.
2. **Order of operations is explicit: working before new.** *"First make sure
   everything already present works."* SuperhostOS's API Worker last deployed
   2026-08-09 with commits stacked behind it; `superhostos-db` holds zero rows;
   the compute-decay faculty is idle rather than faulty for exactly that reason.
   That is the "already present" this line points at.
3. **Consolidation is a live question, not a settled architecture.** *"Blend
   HostOS-MCP with HostOS, or just decide what deserves existing."* The second
   half of that sentence is the instruction. Four agent Workers hold account API
   tokens; two of them have no source in any repository at all. Deciding what
   deserves to exist is the cheapest security work available on this account.
4. **The door is not decoration.** *"Make sure all can be seen in one glimpse"*
   is written as an Intent with its own Pattern — the founder is holding the
   three-line form to the same standard as everything it governs.

## The token line, recorded the day it was said

Alongside this page, on the same day:

> *"Most token gates should not exist in the first place."*
> *"I want as less tokens in the system as possible… nobody needs that many
> keys, one solid transparent system can run an enterprise."*
> *"I personally carry zero tokens, as the vision was to be purely autonomous —
> a human user is the first target of a cyber breach."*

This is founder direction and it is not conditional. It reads against the
current state as follows, stated plainly rather than softened:

- The founder holds **no** credentials. Every standing token on this account is
  held by machines, injected into agent environments, or set as a Worker secret.
  There is no human-held key to phish; there is also no human in the path of a
  rotation, which is why rotations have not happened.
- A standing credential is *"permission asserted forever and proven never"* —
  the org door already says this. Most gates in this system are standing
  credentials guarding routes that could instead prove authority per call.
- **What is genuinely blocked, and by what:** rolling a token invalidates the
  running session's own injected credentials, and Cloudflare shows a new value
  exactly once. So the roll needs a destination that survives the session that
  performs it — Cloudflare Secrets Store, or the founder taking the value at the
  moment it is shown. That is one decision, not a project, and it is the only
  thing standing between this line and being done.
